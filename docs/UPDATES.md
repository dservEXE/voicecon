# Обновления Voicecon через GitHub

Источник: https://github.com/dservEXE/voicecon/releases

## Для пользователя

Один раз установите Voicecon 0.6.1 или новее через `Voicecon-Setup.exe`. Эта версия использует новый адрес владельца `dservEXE`; сборку 0.6.0 после переименования аккаунта нужно один раз обновить установщиком. Дальше приложение проверяет последний стабильный релиз при запуске (если предыдущая проверка была более 6 часов назад). Проверку можно запустить вручную в «Настройки → Обновления» или отключить.

При появлении новой версии на вкладке «Звонок» сверху появляется яркая кнопка «Обновить». «Позже» скрывает уведомление об этой версии; кнопка в настройках остаётся. Более новый релиз сможет показать уведомление снова. Установка всегда добровольная, сама не начинается и не прерывает звонок. Во время звонка кнопка установки недоступна.

По нажатию приложение скачивает только установщик текущего релиза, проверяет размер и SHA-256 из API GitHub, сверяет версию и продукт. Затем завершает свой процесс и запускает обновление без дополнительных окон установки. Обновлённый клиент открывается снова. Запуск и проверка обновления не требуют Git, аккаунта GitHub или токенов на компьютере друга.

Установленная версия заменяется в `%LOCALAPPDATA%\Programs\Voicecon\Voicecon.exe`. Контакты, ключи и настройки в `%LOCALAPPDATA%\Voicecon` сохраняются. Автозагрузка и существующий ярлык сохраняют прежнее состояние. Скачанный установщик удаляется после выхода помощника установки. Временная копия для восстановления удаляется после успешного запуска новой версии. Ошибка загрузки/контрольной суммы не запускает установку и удаляет незавершённый пакет.

Из старого формата настроек имя один раз заменяется на «Игрок», чтобы старое автоматически подставленное или перенесённое имя не оставалось значением по умолчанию. После этого выбранное пользователем имя сохраняется. Чистая установка не использует имя Windows. Профили пользователей не входят в установщик и репозиторий.

Переносной запуск тоже может предложить обновление: после него приложение устанавливается по стабильному пути, принадлежащий ему ярлык переводится на установленный файл, исходный переносной `Voicecon.exe` или `Voicecon-<версия>.exe` удаляется. Произвольно переименованные сторонние файлы автоматически не удаляются.

Начиная с 0.6.1 обычная установка также удаляет старый переносной EXE, если она завершила именно этот процесс и успешно установила приложение. Удаляются только файлы Voicecon с каноническим именем и проверенными сведениями о продукте; поиск по чужим папкам не выполняется. Установка и обновление используют общую блокировку, заменяют установленный EXE атомарно и сохраняют временную копию до завершения установки.

## Как выпускать следующую версию

1. Измените код и увеличьте `<Version>` в `src/Voicecon/Voicecon.csproj`, например до `0.6.5`.
2. Сохраните изменения в ветку `main` на GitHub. GitHub Actions проверит код, соберёт приложение и опубликует релиз `v0.6.5`.
3. Либо откройте **Actions → Build and publish Voicecon → Run workflow** после изменения номера версии. Существующий релиз с тем же номером повторно не перезаписывается.

В релиз автоматически входят `Voicecon-Setup.exe`, `Voicecon.exe` и `SHA256SUMS.txt`. Клиенты используют API `releases/latest` и автоматически вычисленный GitHub digest актива `Voicecon-Setup.exe`. Черновики, предварительные версии и старые номера не предлагаются как обновления. Политика доступа к обновлениям опирается на HTTPS и права записи владельца репозитория.

В первый запуск workflow сохраняет проверенный исходный архив FFmpeg в отдельный предварительный релиз `media-runtime-v1`. Он не предлагается как обновление приложения. Это фиксирует зависимость для будущих сборок без хранения больших DLL в исходниках. Исходный архив проверяется по SHA-256 в `prepare-media.ps1`; набор лицензий и сведения об исходниках находятся в `media/`.

GitHub Actions использует временный `GITHUB_TOKEN` только в своём процессе сборки, с доступом к этому репозиторию. Этот ключ не включается в Voicecon. Приложение выполняет только публичные HTTP GET-запросы к GitHub.

## Локальная сборка

```powershell
.\prepare-media.ps1
.\check.ps1
.\build.ps1
.\build-installer.ps1
```

Результаты текущей сборки находятся в `artifacts/Voicecon.exe`, `artifacts/Voicecon-Setup.exe`; промежуточная папка `artifacts/publish` используется повторно, архив старых сборок не создаётся. Для проверок обновления: `dotnet run --project tests/Voicecon.Checks -c Release -- --update-checks`.

Для удаления старых локальных сборок и временных инструментов есть `cleanup-local.ps1`: без параметров он только показывает список, с `-Apply` удаляет перечисленные генерируемые файлы. Исходники, профиль, контакты и рабочая переносная версия 0.5 сохраняются. Активные процессы и пути с reparse points дополнительно проверяются перед очисткой. Локальные инструменты и встроенный media-runtime.zip можно повторно получить через подготовку среды и `prepare-media.ps1`; сборка на GitHub от локальных файлов не зависит.
